## Scope

Design §4 (`docs/superpowers/specs/2026-09-20-agent-surface-design.md`). `kilasflow <verb>` becomes the agent surface while `kilasflow` with no subcommand keeps meaning "serve" (the container entrypoint and every Compose file depend on it; `-config`/`-version` keep working).

## Acceptance criteria

- [x] Command tree per §4.2 for phase 1: `context`, `health`, `version`, `auth`, the read-only verbs, and the run/observe verbs that need no new API operation.
- [x] `kilasflow api <operation-id>` reaches every operation id in `docs/src/content/docs/reference/api-contract.md` (§4.3), with a test that walks the contract.
- [x] Output contract (§4.4): `--json` envelope stable and documented; exit codes per §4.5, including a distinguishable code for a refused scope.
- [x] Config and token handling per §4.6: precedence, storage, and that a token is never printed or accepted on argv where avoidable.
- [x] Guardrails per §4.7: guarded verbs refuse without `--yes`.
- [x] `bin/kflow` (a stale build of the server binary) is removed; no `kflow` alias is added.
- [x] `make smoke-cli` drives context → workflow create → run --wait → exec trace against a booted server and asserts exit codes and the envelope.

## Out of scope

Scoped tokens (phase 2), debug primitives that need new operations (phase 3).

### Stage 2 of 4 — `api <operation-id>`, the contract walk, and `context`

What changed:

- `internal/cli/openapi.go` (new): `Operation` and `Client.Operations`, which reads `<base>/api/openapi.json` from the **running** server at call time, indexes `paths` by `operationId` (unreadable document, duplicate id or empty surface -> an error, never a guess) and caches the index on the Client, which is one invocation. `resolveOperation`/`fillPath` substitute and URL-escape every `{name}`, refuse a placeholder with no `--path` as exit 2 `usage` (`operation <id> needs --path <name>=<value>`), ignore a leftover `--path`, and merge the query.
- `internal/cli/verbs_api.go` (new): the `api` verb. `--list` (sorted ids the server serves; `--quiet` prints one per line), repeatable `--path`/`--query`/`--header name=value`, `--body <json>|@<file>|-`, `--body-file`, `--out <path>|-`. A JSON response is carried unmodified under `data`; a non-JSON one as `data.raw` (base64) plus `data.contentType`; `--out <path>` writes the bytes and reports the path; `--out -` writes them to stdout with no envelope. An unknown operation id is refused with exit 2 `usage` before the operation request; a server refusal is carried through unchanged (403 -> exit 3 `scope_denied`, problem verbatim); `meta.operation` is the resolved operation id.
- `internal/cli/context.go` (new): the `context` verb — `cli`, `server` (`url`, `ready`, the `get-health` body), `identity` (`tenantId`, `kind`, `label`, `keyId`, `userId`), `workflows` and `datastores` (capped at 20, `truncated` from `X-Next-Cursor`), `nodeTypes` (count). Every section fails independently into its own `error`; readiness is the only fatal one, and a payload a section cannot read is a section error rather than an empty list.
- `internal/cli/cli.go`: `Context.Operation` (a run-time-resolved id overrides the verb's own in `meta.operation`) and `Context.Streamed` (a verb that already wrote raw bytes suppresses the envelope); `operationOf` reads the Context. `internal/cli/client.go`: the index cache field. `internal/cli/command.go`: both verb families registered.
- `docs/src/content/docs/reference/cli.md`: the two verbs marked available, sections for `api` and `context`, `api --out -` added to the documented envelope exceptions, and one factual correction — the page claimed `GET /workflows/{id}/webhooks` "does not exist yet"; it is served as `list-workflow-webhooks` and the walk proves it (the `webhook list` verb still waits on FEAT-77rveq).

Deviations from the stage-2 plan, recorded so the owner can overrule:

1. `kilasflow api --list | wc -l` prints **1**, not 74: a pipe is not a terminal, so the output contract turns the listing into the envelope. `api --list --quiet | wc -l` prints 74 (one id per line) and `api --list --json` carries `data.operations` (74 ids) with `data.count`. The plan's doneWhen command contradicts design §4.4; `--quiet` is the contract's own pipeline form, so no new exception was invented.
2. The unknown-id refusal costs **one** request — the `/api/openapi.json` read that makes the refusal possible — and never a request to the operation. The plan asked for "zero requests"; zero is only reachable from a compiled-in id list, which the same plan forbids ("never a compiled-in list"). Both halves are pinned by tests: with a pre-seeded index the refusal sends nothing at all, and otherwise the only request is the index read.
3. The walk does not assert `exit != 2` for every row. 23 of the 47 are operations with a required body, and huma answers a body-less call with `422`, which the exit contract maps to 2 (`bad_request`). Instead every row asserts `meta.operation` is the row's id, that the refusal is never the unknown-id `usage` one, and that the answer is a problem document or a non-HTML body. The 11 GET rows without a path parameter additionally assert `exit != 2`.
4. `context` carries six sections (`cli`, `server`, `identity`, `workflows`, `datastores`, `nodeTypes`); the plan's prose says "five" but its own JSON literal lists six, and the literal was implemented.
5. `--out` takes a file path as well as `-`: the plan's prose names only `--out -`, and a flag that accepts one value needs a meaning for the other.

Open for the owner (the plan's unanswered `decisionsForOwner` items; each implemented at the plan's stated default): the exit codes for 400/401/422/429; `run --wait` on a failed execution (stage 3); whether guarded-verb unit tests satisfy criterion 5 (stage 4); the scope line of stage 4's verb list; which operation `auth login` drives (stage 3); the streaming exceptions, now three with `api --out -`; the `github.com/BurntSushi/toml` (MIT) dependency (stage 3); `make smoke-cli`'s CI wiring (stage 3).

### Stage 3 of 4 — config and token handling, the auth verbs, the workflow read verbs + create, the run/exec verbs, `make smoke-cli`

What changed:

- `internal/cli/config.go` (new): `Settings` and `resolveSettings`, which apply the chain exactly — `--url`/`--token` → `KILASFLOW_URL`/`KILASFLOW_TOKEN` → the file `--config` names (replacing the default path, not merging) → `~/.config/kilasflow/config.toml` → the built-in `http://127.0.0.1:8080`. An explicitly empty `--url ''` means "no server"; `--config ''` means no file; `--token` and `--token-file` are one rung and passing both is exit 2. `readTokenFile` refuses a file whose mode is not `0600` (naming the `chmod`), `saveConfig` writes `0600` **and** chmods afterwards so an existing 0644 file is tightened, with the directory at `0700`, rendered through TOML so an awkward token round-trips. One resolution per invocation, cached on the `Context`, so the client and the credential verbs cannot disagree. `defaultConfigPath` is `$HOME/.config/kilasflow/config.toml` deliberately, not `os.UserConfigDir` (darwin would answer `~/Library/Application Support`).
- New direct dependency `github.com/BurntSushi/toml v1.6.0` (**MIT**, no transitive requires), per the plan's decision: hand-rolling a TOML parser was the alternative and is worse.
- `internal/cli/verbs_auth.go` (new): `auth login` (token from `--token -`/stdin, `--token-file`, or `KILASFLOW_TOKEN`; `--token <value>` refused as exit 2; validated against `get-me` before anything is written; prints `url`, `tenantId`, `kind`, `configPath`), `auth logout` (removes `token`, keeps `url`, a no-op without a file), `auth whoami` (`get-me`, projected to `tenantId`/`kind`/`label`/`keyId`/`userId`). `login`/`logout` carry Operation `""` because the API's `login`/`logout` operations are browser-cookie operations, not what this stores — recorded for the owner.
- `internal/cli/verbs_workflow.go` (new): `workflow list|get|create|versions|get-version|publish-events|export|diagnostics`, each addressing the stable documented path (one request, not a document lookup). `create --file <path>|-` sends the document unchanged and refuses a non-JSON one before a request; `--quiet` prints the id the API named in `Location`. Listings normalise the API's two page shapes (bare array + `X-Next-Cursor` vs `{items, nextCursor}`) into `{items, count, nextCursor}`. `update|restore|import|duplicate|validate|activate|deactivate|delete` and a webhook verb are deliberately not registered.
- `internal/cli/verbs_run.go` (new): `run <workflowId>` with `--input`/`--input-file`/`--trigger`/`--wait`/`--poll`. The body is `{"input":…,"triggerNodeId":…}` and is omitted entirely when there is nothing to say. `--wait` polls `get-execution` until `succeeded` (exit 0, `data` = the finished record), `failed`/`cancelled` (exit 1, `error.code = "execution_failed"`, the record under `error.detail.execution`), or the deadline (exit 1, `error.code = "timeout"`, naming the execution). `queued`, `running`, `cancelling` and `waiting` are not terminal. The wait deadline is `--timeout` when given and five minutes when not, because waiting is the one thing this CLI does that is expected to take minutes. `--quiet` prints the execution id **before** the wait starts, so a pipeline can trap it.
- `internal/cli/verbs_exec.go` (new) + `internal/cli/sse.go` (new): `exec list` (`--workflow`, repeatable `--status`, `--trigger`, `--limit`, `--cursor`), `exec get`, `exec cancel` (not guarded: it stops work rather than publishing or destroying anything), `exec trace` (one envelope: `{executionId, events:[{id,event,data}], terminal, lastEventId}`, stopping at the outcome rather than at the close; a deadline is not a failure — it answers `terminal:false` with the id to resume from) and `exec tail` (the documented NDJSON exception: one object per line in JSON mode, one text line otherwise, exit 0 on the outcome and 6 when the deadline passes or the feed closes early). `--from <id>` is sent as the standard `Last-Event-ID` header. The SSE reader handles comments (the server opens with one), `retry:`, CRLF, multi-line `data:`, frames with no data, and a payload that is not JSON; both stream verbs bound themselves, because a feed for a live run never closes on its own.
- `internal/cli/client.go`: `Do` and the new `Stream` share one `buildRequest`; `Stream` returns the live response for the stream verbs and turns a non-2xx into the same `ExitError` `Do` produces. A problem document is now redacted against the client's own token before it is carried — the one path by which a credential could reach an envelope from outside the CLI — and a non-JSON error body is redacted too.
- `internal/cli/cli.go`: `Context.resolved` (one settings resolution per invocation), `Context.bound(after)`/`deadlineExceeded()` (the invocation deadline, with the per-request HTTP timer switched off so a stream is not cut short by a timer meant for one request), `buildClient` now built from `resolveSettings`, and a streamed invocation's failure is reported on stderr rather than as an envelope appended to the byte stream. `ExitError.Execution` and `ErrorDetail.Execution` carry the record of a run that failed.
- `internal/cli/verbs_system.go`: the missing-URL refusal now names all four ways to set one (`--url`, `KILASFLOW_URL`, `--config <path>`, the default path).
- `docs/src/content/docs/reference/cli.md`: the stage-3 rows marked available, new sections for `auth`, `workflow`, `run` and `exec`, `error.detail.execution`, the corrected config chain (`--config` replaces, `0600`/`0700`, the argv refusal), the corrected `exec tail` NDJSON shape, and the note that no phase-1 verb is guarded.
- `scripts/smoke-cli.sh` (new) and one appended Makefile target `smoke-cli`.

Deviations from the stage-3 plan, recorded so the owner can overrule:

1. The plan's operator key for the smoke, `kfa1_smoke_operator-secret-value`, is **refused by this tree**: `auth.SplitKey` requires the middle segment to be hex, and `repository.EnsureAPIKey` refuses anything else (`an API key token must be shaped like kfa1_<hex prefix>_<secret>`). The smoke uses `kfa1_5f3a2b1c9d4e6f708192a3b4c5d6e7f8_smoke-operator-secret`, which is the plan's shape with a real prefix.
2. `--timeout` keeps the meaning it already had — the deadline for one invocation — instead of gaining a second, verb-local one. `run --wait` uses it as the wait deadline when the caller passes it and defaults to five minutes otherwise (so `run … --wait --timeout 60s` means what the plan's smoke expects), `exec trace` defaults to the flag's own 30s, and `exec tail` has **no** deadline unless the flag is passed (which is what the plan asks for, and the only reading under which `--timeout 0` and "until the run ends" agree). The verbs set the deadline on the context and switch off the HTTP client's per-request timer, because a stream cut off by a 30s timer is indistinguishable from a run that ended.
3. `exec trace` exits 0 when its deadline passes with the run unfinished, carrying `terminal:false` and `lastEventId` in the envelope. The plan says the deadline must not hang an agent but does not say what trace should exit; the envelope it defines already carries the fact, and the exit code stays for `exec tail`, which has no envelope to carry it in.
4. A listing's payload is `{items, count, nextCursor}` rather than the operation's body verbatim: the API answers a workflow listing with a bare array and the cursor in a header, and revisions with an object carrying both. One shape is what lets an agent loop every listing the same way; the items themselves are unmodified.
5. `workflow list`, `workflow versions` and `exec list` take the `--limit`/`--cursor` the operations have; `workflow publish-events` has neither in the API and takes none. `workflow export` takes `--format`, `workflow diagnostics` takes `--version-id`, because both operations have those query parameters and a verb that hides them would force a caller into the escape hatch.
6. `exec tail`'s `--quiet` has no separate meaning: every line it writes is the output, so it renders the same human line per event as a terminal would. Documented on the reference page.
7. `auth login` prints `tenantId` as its `--quiet` value and stores the URL it resolved (including one that came from a flag or the environment), so the file is a complete record rather than half of one.

Not in this stage (unchanged criteria): the remaining read-only families (`node`, `credential`, `datastore`, `schedule`, `tenant`, `pack`) and the `--yes` guard primitive are stage 4; criterion 1 is proven only for the verbs registered so far (`TestStageThreeVerbFamilies` pins this stage's mapping, and the complete phase-1 registry assertion belongs to the final stage).

### Stage 4 of 4 — the remaining read-only verbs and the `--yes` guard primitive

What changed:

- `internal/cli/verbs_node.go` (new): `node list` and `node describe` -> `list-node-types`, `node options` -> `load-node-property-options`. Two views of one operation is the documented reverse of the one-verb-per-operation rule, and both verbs name the operation they call, so the tree test asserts the sharing rather than tolerating it. `describe` needs no version argument: of a type registered at several versions it answers with the one the server resolves a document without a version to (the highest), so the definition printed is the definition that would run. An unknown type exits 4 `not_found` with the nearest catalogue names (edit distance <= 2, at most 5, none when nothing is close). The catalogue operation takes no parameters, so `node list` takes none either, and `--quiet` prints one type per line — the value `describe` accepts.
- `internal/cli/verbs_credential.go` (new): `credential list` (page flags), `credential get`, `credential test` (a POST with no body — the probe reads the stored credential, so the secret is never sent back to be tested; `--quiet` prints the API's own boolean). No `create`/`update`/`delete` (phase 2, guarded) and no `types` (`api list-credential-types` and `api test-credential-payload` cover it).
- `internal/cli/verbs_datastore.go` (new): `datastore list`/`get`/`rows` and `datastore export` (`GET /datastores/{id}/rows/export`, the tree's path). `--out` defaults to `-`, which streams the CSV bytes raw — the second documented envelope exception — and `--out <path>` writes the file `0600` and reports `{path, bytes, contentType}`.
