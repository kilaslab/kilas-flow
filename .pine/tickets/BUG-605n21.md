## OPS-17: Datastore datetimes show as raw UTC ISO next to localized system timestamps, and the export filename uses the id

*ux · low · datastores*

**n8n:** Dates render in one consistent local format, and exports are named after the table.

**Steps to reproduce:**

1. Add a row with signed_up = 2026-09-01 10:00 (datetime-local, browser at +07:00). 2. Look at the grid. 3. Export.

**Actual:**

The cell shows "2026-09-01T03:00:00Z", while createdAt shows "Sep 23, 08:06:43 AM" in the same row. The download is named `datastore-datastore_01a0cbca-186a-7138-bb4b-4005b32d0927.csv`.

**Expected:**

The same localized format as createdAt (ISO on hover), and "[ux-ops] Leads.csv".

**Suggested fix:**

Format date-typed user columns with the same helper as the system columns, and build the filename from detail.name.

**Evidence:**

agents/ux-ops/25-datastore-row.png, agents/ux-ops/31-datastore-grid.png, agents/ux-ops/.playwright-cli/datastore-datastore-01a0cbca-….csv.

**Related:**

BUG-esb9sh (done). Its evidence lists both issues ("User datetime values appear as raw ISO…", "export filename uses the datastore id"), and both still reproduce.


## OPS-26: Terminology and copy: "Datastores" vs "Data table", and developer-facing sentences in dialogs

*ux · low · dashboard*

**n8n:** "Data tables" everywhere: nav, node and docs.

**Steps to reproduce:**

1. Compare the sidebar ("Datastores"), the node picker ("Data table", "Data table Tool") and the CLI help ("create a data table"). 2. Open Add column, Delete datastore and Import rows.

**Actual:**

One feature has two names. The dialog copy reads like implementation notes: "A name and a type. Nothing offers nullability, uniqueness, or a default." / "Cancelling sends no request and leaves the datastore untouched." / "a file carrying id, createdAt, updatedAt or dryRunState is refused" (dryRunState is an internal column). The Data table node's description is a paragraph about row-lock semantics. The export dialog has two buttons named "Close". Export with system columns is recommended "for a backup", but import refuses exactly that file, so a backup can't be restored.

**Expected:**

One user-facing name ("Data tables") and task-level copy. An import that can restore its own backup, or no "backup" wording.

**Suggested fix:**

Rename the nav and page titles to "Data tables" (keep the /datastores routes) and rewrite the three dialog descriptions.

**Evidence:**

agents/ux-ops/20-datastore-new.png, agents/ux-ops/27-export-dialog.png, agents/ux-ops/28-import-dialog.png, agents/ux-ops/34-ndv-datastore-picker.png.

# Fix

**Root cause.** OPS-16: the header's sort `<button>` already printed `{column.name}` and a `<span>` beside it printed it again. OPS-17: the page's own `cellText` sent only `createdAt`/`updatedAt` through `formatTimestamp`, so a user `date` column fell through to `String(value)`; the export's `Content-Disposition` was built from `"datastore-" + id` on the server, and the client's fallback did the same. OPS-26: the nav, page titles and buttons came from `datastores_*` / `nav_datastores` strings that said "Datastore(s)", and the dialog descriptions were written as implementation notes.

**Change.**
- `web/src/lib/datastore/columns.ts`: new `cellText(value, column)` and `cellHover(value, column)`. Every date column (the two system timestamps and any user `date`/`datetime` column) renders through `formatTimestamp`; the hover is the exact ISO instant. A date value that does not parse shows as written.
- `web/src/routes/(dashboard)/datastores/[id]/+page.svelte`: dropped the duplicate header span, so the header reads "email · string"; cells use `cellText`/`cellHover`; the export passes the table name; the transfer dialog's footer button says "Cancel" before a result and "Done" after one, so it no longer shares the name "Close" with the dialog's X.
- `internal/api/handlers/datastores_csv.go`: `csvExportDisposition` names the download after the table (`[ux-ops] Leads.csv`), turns path separators and control characters into `-`, and uses `mime.FormatMediaType`, which quotes the value and switches to RFC 5987 `filename*` outside ASCII. A blank name falls back to the id.
- `web/src/lib/datastore/transfer.ts`: `filenameFromDisposition` reads `filename*` (preferred) and backslash-escaped quotes; new `exportFilename(name, id)` is the client fallback; `downloadExport` takes the table name.
- Copy (en + id): "Datastores" became "Data tables" ("Tabel data") in the nav, page title, buttons, empty state and errors; `/datastores` routes are unchanged. The add column, delete table, delete column, delete rows, import, export and add row descriptions were rewritten at task level. The system-columns note no longer says "backup": it says a file with those columns can't be imported. `dryRunState` is gone from the import note. `datastores_close` was replaced by `datastores_done`. The e2e specs (`e2e/tests/datastore.spec.ts`, `datastore-pg.spec.ts`) follow the renamed buttons.
- Not changed: the Data table node's long description (`nodes/datastore.go`). It is not dashboard copy, and `nodes/datastore_test.go` deliberately pins its concurrency phrases.

**Tests.** First written to fail, then passing:
- Go: `TestExportFileIsNamedAfterTheTable` in `internal/api/datastores_csv_test.go` covers ASCII, embedded quotes, non-ASCII and path separators.
- vitest: `cellText and cellHover` in `columns.test.ts`; `filename*`, quoted-pair and `exportFilename` cases in `transfer.test.ts`.
- Suites run: `pnpm check` (0 errors), `pnpm vitest run` (59 files / 732 tests), `go test ./internal/api/...`.

**Playwright** (real binary on :18092, auth off):
- Headers read `id`, `email · string`, `score · number`, `signed_up · datetime`, `createdAt`, `updatedAt`.
- A row with signed_up = 2026-09-01 10:00 (browser +07:00) shows "Sep 1, 10:00:00 AM" with title "2026-09-01T03:00:00Z — click to edit". createdAt in the same row shows "Oct 8, 10:57:07 PM".
- Export downloaded `[ux-ops] Leads.csv` (`Content-Disposition: attachment; filename="[ux-ops] Leads.csv"`), and the footer then showed "Done".
- The nav, page title and list read "Data tables".
