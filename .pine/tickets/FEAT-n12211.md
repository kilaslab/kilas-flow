# Description

A host's own pack must authenticate against the host API with a named credential type, for example "Acme API" with a non-secret `baseUrl`, a secret `apiKey`, a header placement and a test request. Today packs can only name built-in types (`docs/src/content/docs/concepts/credentials.md:159-205`: "A pack cannot contribute one today"), although the Go registry is already open (FEAT-2f68r8).

# Acceptance Criteria
- [x] The pack manifest accepts `credentialTypes[]` with `{id, displayName, fields (property language, secret and masked flags), authenticate (placement descriptor), test}`.
- [x] Ids are namespaced to the pack and immutable once released.
- [x] `nodepackgen validate` checks the new block.
- [x] The types appear in `GET /credential-types` and work in routing and lifecycle requests.
- [x] The credentials doc is updated.

## Implementation notes (2026-11-26, branch worktree-agent-a98eb59a6f2df4422)

Interpretations (documented in concepts/credentials.md "Credential types from node packs"):
- **Namespace**: id = `<pack.type>.<word>`, word `^[A-Za-z][A-Za-z0-9]*$`, at most 64 chars (credential type column width). No built-in id contains a dot, locked by TestNoBuiltinCredentialTypeIDCanCollideWithAPackNamespace, so a pack type cannot shadow a built-in and only pack `X` can own `X.<word>`. A `credentialType` inside the pack's own namespace must be declared by the pack.
- **Immutability**: enforced part = two installed packs (e.g. two versions) declaring the same id must declare it identically (compared as re-marshalled JSON), else boot refused ("a released credential type is immutable, so give the changed declaration a new id"). Contract part (documented, not enforceable across boots) = never rename/remove a released field key or flip its secret flag.
- **Masked vs secret**: `typeOptions.password` = masked (readable); `secret: true` adds the key to Type.Secrets and also masks. GET /credential-types shape unchanged. A pack may not declare `dial` or `neverSentOverHttp` (unknown keys).
- Only directory packs register types (LoadDir); nodepack.Register (embedded path) does not.
