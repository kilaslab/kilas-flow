### Expression grammar covers only a small subset of what n8n workflows use (no operators, JS methods, Luxon, n8n extension functions, JSON encoding) [find:expression-parity] (critical/parity-gap) · area: expression engine · confidence: high

### Lone {{ $now }} / {{ $today }} leak an opaque Go struct: Set string -> "{}", DateTime and IF nodes reject it as 'not a date' [find:expression-parity] (high/bug) · area: expression engine / date values · confidence: high

A template that is only `{{ $now }}`, `{{ $today }}` or `{{ $now.plusDays(n) }}` returns the evaluator's unexported dateValue struct. The Set node JSON-marshals it to the string "{}". The DateTime node and IF/Filter date conditions only accept time.Time, string or number, so they fail.

Evidence: internal/expression/functions.go:16 (dateValue with unexported field); nodes/assignments.go:101-111 (json.Marshal fallback); internal/datetime/parse.go:60-79; internal/conditions/conditions.go:518-541. Live (t_dates.py -> dates-kf.json vs dates-n8n.json): Set string `{{ $now }}` gives KF "{}" vs n8n "2026-09-19T15:36:41.792+07:00", and the same for $today and $now.plusDays(1). DateTime addToDate with magnitude `{{ $now }}` gives KF 'item 1: 2026-09-19T08:35:38Z is not a date'; n8n returns newDate. IF dateTime 'after' with left `{{ $now }}` gives KF 'condition left value is not a date'; n8n routes true. Template 1744 is one of only 4 templates that activate, and its run fails at node '12 Hours from now' with the same error (exec_01a0b8cc-8f30-7f26-994c-d3a2fa10f477).

n8n behavior: $now/$today are Luxon DateTimes. They serialise as ISO with millis and offset (e.g. 2026-09-19T15:36:41.792+07:00) and are accepted by DateTime and IF date comparisons.

Impact: $now is used in 36 params / 22 templates and $today in 5/3. Schedules, date filters and timestamps written to sheets or DBs are corrupted or fail.

Suggested fix: Never let dateValue escape Evaluate: turn a lone date into time.Time (or an ISO string with millis and offset) before returning. Teach datetime.Parse and conditions.asTime to accept it. Add tests for Set/DateTime/IF fed from `{{ $now }}`.

### Allowlisted functions share JS names but not JS semantics (replace, includes, stringification, escapes, .length, join) [find:expression-parity] (high/bug) · area: expression engine / functions · confidence: high

Several allowlisted functions silently give different results from n8n under the same name. replace replaces every occurrence instead of the first. includes() on arrays compares stringified text. Objects and arrays placed in text render with Go %v syntax. Single-quoted arguments keep backslash escapes. .length works only as a KF-only call. join() requires a separator.

Evidence: functions.go:61 (replace = strings.ReplaceAll), :70-83 (includes compares stringify(entry) == args[0].text), :114 (join arity 1), :85 (length as a call); expression.go:644-665 (stringify default fmt.Sprintf("%v")). Live diff.json: p20 `email.replace('a','A')` n8n 'AdA.Lovelace@Example.com' vs KF 'AdA.LovelAce@ExAmple.com'. p90 `replace('.', '_')` n8n 'Ada_Lovelace@Example.com' vs KF 'Ada_Lovelace@Example_com'. p23 `[3,1,2,2].includes(2)` n8n true vs KF false; p87 includes('2') n8n false vs KF true. p12 'Tags: {{ $json.tags }}' n8n 'Tags: alpha,beta,gamma' vs KF 'Tags: [alpha beta gamma]'. p11 object renders as 'map[city:London ...]'. p64 `join('\n- ')` gives a literal backslash-n on KF. p84 `join()` gives KF error 'join() takes 1 argument(s), got 0'. p14/p15/p80 `.length` gives '$json.tags.length is not an object', while p16 `.length()` is rejected by n8n. harness/edge: `replace('', '-')

n8n behavior: Standard JavaScript String/Array semantics (see the probe values above).

Impact: The results are silently wrong, with no error. replace and includes appear in many parse-OK params. .length is used in 10 params / 6 templates. Arrays interpolated into prompts and messages change format.

Suggested fix: Match JS semantics for every function that keeps a JS name: replace = first occurrence (add replaceAll), includes with type-strict equality for numbers and bools, join default ',', `.length` as a property, JS escape handling in single-quoted literals, and JS-like stringification (arrays comma-joined, objects as JSON rather than Go syntax). Add a parity table test.

### $input API is KilasFlow-specific: $input.item silently undefined, $input.first()/last()/all() error, $('X').params silently empty [find:expression-parity] (high/parity-gap) · area: expression engine / $input and node accessors · confidence: high

KF's $input is a map of port to items (`$input.main[0].x`). n8n's API ($input.item, .first(), .last(), .all(), .params) does not exist. `.item` and `.params` resolve to undefined without an error. `.isExecuted` and `.itemMatching()` are also missing.

Evidence: expression.go:531-540 (rootValue $input); internal/expression/expression_test.go:44 uses `$input.main[1].name`. Live batch2: q05 `$input.item.json.v` gives n8n a,b,c vs KF '' (silent). q06/q07/q14 `$input.first()/all()[2]/last()` give KF 'first() needs a list or a node'. q10 `$('Split Out').isExecuted` gives n8n true vs KF type error. q11 `$('Split Out').params.fieldToSplitOut` gives n8n 'list' vs KF '' (silent).

n8n behavior: $input.item is the current input item; $input.first()/last()/all() read the node's main input; $('X').params gives the node's parameters; isExecuted is a boolean.

Impact: $input.all 9 params / 7 templates and $input.item 3 / 2 in the template corpus. $input is also the dominant idiom in n8n docs and in user-written expressions, and the silent cases produce empty data.

Suggested fix: Implement n8n's $input surface on the current node's input (item = current item, first/last/all over the main input, params = own parameters) while keeping `$input.main[...]` for back-compat. Add `$('X').isExecuted`, `.params` and `.itemMatching(i)`.

### $now/$today ignore the workflow timezone (always UTC) and stringify without millis [find:expression-parity] (medium/bug) · area: expression engine / dates · confidence: high

The engine never sets expression.Context.Now, so $now is time.Now().UTC(). $today is the start of the UTC day even when the workflow carries settings.timezone, which the importer preserves. Mixed-text rendering drops milliseconds and the offset.

Evidence: internal/engine/authenticate.go:94-103 (no Now/location); expression.go:616-621 clock() returns time.Now().UTC(). Impact: $today falls on the wrong calendar day for part of every day outside UTC. Date-bucketed reports, 'today's' queries and filenames are affected. $now is in 22 templates and $today in 3.

Suggested fix: Build Context.Now in the workflow's timezone (settings.timezone, then instance default, then UTC) and compute $today in that zone. Render dates the way n8n does (ISO with millis and offset).

### $now.format() takes Go layouts, not Luxon tokens, so imported patterns silently return the pattern text [find:expression-parity] (medium/bug) · area: expression engine / date formatting · confidence: high

format(...) calls Go's time.Format. An imported Luxon pattern like 'yyyy-MM-dd' comes back unchanged as the literal 'yyyy-MM-dd', and '2006' is turned into the current year. The difference is documented but neither flagged at import nor refused. KF-only helpers (plusDays, minusDays, toISOString) also break when exported to n8n.

Evidence: functions.go:152-158. Live p36 `$now.format('yyyy')` gives n8n '2026' vs KF 'yyyy'. p37 `format('2006')` gives n8n '2006' vs KF '2026'. harness/edge `format('yyyy-MM-dd')` gives 'yyyy-MM-dd'. p40 `$now.plusDays(1).format('2006-01-02')` and p82 `toISOString()` give null on n8n. Documented at docs/src/content/docs/concepts/expressions.md:176-179, and doc.go uses `$now.plusDays(7).format("2006-01-02")` as the example.

n8n behavior: DateTime.format/toFormat use Luxon tokens (yyyy, MM, dd, LLL...).

Impact: .format( appears in 8 params / 6 templates (e.g. `$today.plus({days: 14}).format("d. MMM. y")`, `$now.format('dd/LL/yyyy')`), and every exported KF workflow that uses format or plusDays breaks on n8n.

Suggested fix: Accept Luxon tokens in format/toFormat (translate the token set). At minimum, refuse or flag patterns that contain Luxon tokens instead of echoing them. Rename KF-only helpers or add n8n-compatible names (plus/minus with a duration object).

### URLs built from expressions are sent without percent-encoding, and upstream rejects them [find:expression-parity] (medium/bug) · area: HTTP Request node / expression interpolation · confidence: high

After interpolation the URL goes through url.Parse unchanged. The query is re-encoded only when sendQuery is on, so a value with a space or other reserved character yields an invalid request line.

Evidence: nodes/http.go:224-237. Live (t_http.py url_expr): url `=http://127.0.0.1:8092/echo?v={{ $json.x }}` with x='hello world' gives KF 'request failed with status 400' (the raw space is on the request line). n8n requests /echo?v=hello%20world and succeeds.

n8n behavior: n8n (axios) percent-encodes invalid characters in the resolved URL.

Impact: 91 HTTP URLs in 33 templates are built from expressions, e.g. template 2431 `https://www.google.com/search?q=site:{{ $json['Website Domaine'] }}+{{$json.Subject}}` and template 1750's Google URL. Any value containing spaces, accents or quotes fails.

Suggested fix: Normalise the URL after interpolation: re-encode the path and query components that contain invalid characters, like browsers and axios do, without double-encoding existing %XX.

## Progress — ExpressionParity slice (internal/expression, internal/engine/authenticate.go)

Scope owned by this slice: `internal/expression/*.go` and
`internal/engine/authenticate.go`. Findings whose fix lives in another slice's
files are listed with the owner that was asked, not silently dropped.

### Landed (commit 1 — expression engine rewrite)

- **Grammar (critical)**: replaced the root+accessors grammar with a
  tokeniser/parser/evaluator for the JavaScript expression subset. New syntax:
  binary/arithmetic/comparison/equality operators, ternary, `??`, `&&`, `||`,
  optional chaining `?.`, template literals, array and object literals, spread
  in call arguments, arrow functions, unary `!`/`-`/`+`, and expression
  arguments in calls. `internal/expression/parser.go`, `evaluator.go`.
- **JS semantics**: `+` (text vs arithmetic), truthiness, `==` vs `===`,
  ordering, `??` looking past null/undefined only, NaN/Infinity rendering.
- **Function semantics**: `replace` = first occurrence, new `replaceAll`,
  `includes` = SameValueZero (not stringified), `join` defaults to `,`,
  `.length` is a property (and `.length()` is refused), single-quoted escapes
  are JS escapes, lists join with commas in text and objects render as JSON.
- **JSON encoding**: `JSON.stringify` (with indent), `JSON.parse`,
  `Object.keys/values/entries/fromEntries`, `Array.isArray/from`,
  `Math.*` (incl. `min`/`max`/`hypot`/`PI`), `Number/String/Boolean/parseInt/
  parseFloat/isNaN/encodeURIComponent/decodeURIComponent`, `toJsonString()`.
- **List methods**: `map`, `filter`, `find`, `findIndex`, `some`, `every`,
  `reduce`, `flat`, `flatMap`, `reverse`, `concat`, `slice`, `at`, `sum`,
  `removeDuplicates`/`unique`, `count`, `first`/`last`/`all`.
- **Dates**: `$now`/`$today` stringify as ISO 8601 with milliseconds and an
  offset; a lone `{{ $now }}` is returned as `time.Time` (no more `{}` in a Set
  node, no more "not a date" in DateTime/IF); a nested date marshals via
  `MarshalJSON`. Luxon tokens for `format`/`toFormat` (yyyy, MM, dd, LLL, EEEE,
  Z, …) instead of Go layouts; `plus`/`minus` with a duration object or a unit;
  `startOf`/`endOf`; `toISO`/`toISODate`/`toISOString`/`toMillis`/`toSeconds`/
  `toJSDate`/`setZone`/`diff`; Luxon getters (`$now.year`, `$now.weekday`);
  `DateTime.now/local/utc/fromISO/fromMillis/fromSeconds/fromFormat/fromJSDate`.
- **Timezone**: `expression.Context.Timezone` (new) is read by the clock;
  `authenticate.go` fills it from `Request.Workflow.Timezone`, so `$now`/
  `$today`/`DateTime.local()` are in the workflow's zone.
- **Undefined semantics**: an index past the end of a list or a string, and a
  field read on a scalar, are undefined instead of a hard failure. A string
  index returns the character, as JavaScript does.
- **Parser robustness**: quote-aware scanning for `)`/`]` inside string and
  template literals, Unicode identifiers (`$json.título`), escaped quotes.
- **$env**: reads the allowlist map; a key that is not there is a loud error
  naming `KILASFLOW_WORKFLOW_ENV_<KEY>` instead of resolving to `""`.
- **$input**: n8n's API added on top of the port map — `.item`, `.first()`,
  `.last()`, `.all()`, `.isExecuted`; `$items('Name')` added.
- **$node / $('X')**: `$node["X"].json` reads the paired item when the runtime
  established lineage and otherwise the item at the same position (never the
  first item for every current item). `.params` and `.isExecuted` added;
  `NodeItem.ItemOrigins` + `expression.OriginKey(...)` exported for the runtime's
  pairing; `.item` still refuses to guess.
- **Roots**: `$vars`, `$runIndex`, `$items` added; `Roots()`/`FunctionNames()`
  still serve the editor.
