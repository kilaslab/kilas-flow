# licensing

- 2026-09-05: LICENCE BOUNDARY — three prohibitions, no exceptions: (1) no n8n source in this repository, not even 'as a starting point' or commented out; (2) no n8n package in any manifest — go.mod, web/package.json, sdk/package.json or a new one; (3) no n8n bytes in any shipped artifact, binary, container image or generated file. And no contact with n8n: do not open issues, ask their team, or seek permission — the boundary is kept by reimplementing, not by negotiating. Enforced by the tests in internal/guardrails (go test -run TestNoN8NDependency ./internal/guardrails), which run inside the ordinary go test ./... every ticket already does.. (cites: internal/guardrails/licence_boundary_test.go)
- 2026-09-05: Read at n8n 2.34.0 (reference checkout 40dfa42, read 2026-09-05): packages/workflow, packages/core, packages/nodes-base, packages/cli, @n8n/nodes-langchain, @n8n/node-cli and @n8n/eslint-plugin-community-nodes every one declares "license": "LicenseRef-n8n-sustainable-use". The root LICENSE.md is the Sustainable Use License v1.0 and additionally carves out every file with '.ee.' in its filename or '.ee' in a dirname, which is not under the SUL at all and needs an n8n Enterprise License per LICENSE_EE.md. KilasFlow's own LICENSE is Apache-2.0 and the product is white-label, multi-tenant and embedded — the configuration n8n's licensing FAQ names as not allowed. Re-verify these facts before trusting them against a newer n8n.
- 2026-09-05: FORMAT may be reimplemented; CODE may not. Format facts are what any second implementation must match to interoperate: connection-type strings like ai_languageModel, the workflow JSON document shape, .node.json codex conventions, resource/operation naming rules, typeVersion semantics, the exact update list a Telegram Trigger offers. Reading those from the reference checkout and writing Go is what every compatible implementation of every format does. Code is the TypeScript that implements them: copying AgentExecutor.ts or a routing interpreter, or importing a type definition from n8n-workflow, is a violation however small the fragment. Test: could you have derived it from observing the wire format? Then it is format.
- 2026-09-05 (list extended 2026-09-23): Vendored third-party bytes are a closed list, and every entry needs its upstream LICENSE and a PROVENANCE.md with sha256 digests, enforced by TestVendoredThirdPartyCarriesItsLicence. The list is: third_party/waha/ (below), third_party/luxon/ (Luxon 3.7.2, MIT) and third_party/lodash/ (lodash 4.18.1, MIT); the last two were added for the embedded JS runtime, EPIC-tjnr1z. @devlikeapro/n8n-nodes-waha is MIT (2025.2.9, upstream commit b06e8f5), so its two openapi.json documents ARE vendored, at third_party/waha/, with the upstream MIT text and a provenance note beside them. devlikeapro/waha-n8n-templates carries no licence file and the GitHub API reports license: null, which is stricter than the SUL rather than looser: those templates are fetched into a gitignored directory when a corpus needs them and are NEVER committed. The same rule covers design-refs/, which is gitignored third-party product UI. (cites: third_party/waha/PROVENANCE.md)
- 2026-09-05: KilasFlow's root LICENSE stays Apache-2.0; nothing in V2 may require changing it. The n8n reference checkout at $KILASFLOW_N8N_REFERENCE and the WAHA clone beside it are read-only specification material: no Makefile target, go:generate, go:embed, test or script may read a path under either, and neither is ever a build input. The one place this boundary is genuinely contested is the deferred JS sidecar ticket (FEAT-7cg0cd, p8), which would execute third-party community nodes — SUL code — in a process this project ships. That question is reopened there and nowhere else; do not treat that ticket as a licence bug, and do not reopen the question anywhere else.
- 2026-09-06: SIDECAR LICENCE POSITION (FEAT-7cg0cd, decided before implementation): operator-installed, never KilasFlow-distributed — KilasFlow ships no JS runtime, no dependency tree, and no community package; the operator installs Node 24 LTS and their chosen packages. The NDJSON-over-Unix-socket protocol in sidecar/ is clean-room with no SUL-derived code, types, or bytes; no new package.json was created (fixture uses node builtins only). Declining the sidecar loses only sidecar-tagged runs (named diagnostic), nothing else. (cites: sidecar/doc.go, FEAT-7cg0cd work evidence)
- 2026-09-06: CONVERTER LICENCE POSITION (FEAT-ed6wdy, decided before implementation): the declarative-description converter reads only an operator-supplied transcription JSON (resource/operation strings, parameter shapes, routing metadata) — format facts under the wire-format test, transcribed by the operator from a package they installed themselves. KilasFlow ships no JS runtime, no community package, and no n8n dependency for this; the converter is a build-time library in internal/nodepack, never on the server boot path, so an unconvertible source is a build-time diagnostic, not a startup failure. No converted third-party bytes are committed to this repository unless their licence independently permits it (same rule as third_party/waha/); converted output carries a Provenance block naming the source type and input digest. A node with a real execute() is refused, never partially emitted.
- 2026-09-23: EMBEDDED JS ENGINE LICENCE POSITION (EPIC-tjnr1z, owner-approved). The two earlier entries that say "KilasFlow ships no JS runtime" are narrowed to **no Node.js runtime**. KilasFlow now links an embedded JavaScript *engine* as ordinary Go modules:
  - github.com/dop251/goja, github.com/dop251/goja_nodejs (buffer and url only) and github.com/dlclark/regexp2, all MIT;
  - golang.org/x/text, BSD-3.

  It also vendors Luxon and lodash (MIT) as bytes under third_party/. It still ships no Node.js, no n8n code or bytes, no npm dependency tree and no community package. The sidecar stays operator-installed Node for programmatic community nodes only, and never runs Code nodes.

  The Code-node globals shim is written from n8n's *documented behaviour* only. No task-runner source is read. n8n-docs snippets are Commons Clause, so none are copied verbatim, including into tests. Real templates used as a test corpus are fetched into a gitignored directory and pinned by digest, never committed.
