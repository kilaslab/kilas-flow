# WAHA node pack

Generated. Do not edit `pack-*.json` by hand — run `make node-packs` and commit
the diff.

| File | What it is |
| --- | --- |
| `manifest-<version>.json` | The decisions the OpenAPI document cannot make: node type, credential mapping, and the two injected parameter defaults. |
| `pack-<version>.json` | The generated pack. Its `generator` block records the SHA-256 of the document it came from, and a test asserts that digest still matches. |
| `REPORT-<version>.md` | Everything in the document that is **absent from the pack**, operation by operation. |

## Provenance and licence

Generated by `cmd/nodepackgen` from WAHA's own OpenAPI documents, vendored under
`third_party/waha/` and covered by the MIT licence committed beside them
(`third_party/waha/LICENSE`). No WAHA or n8n source code is used, and no npm
package is installed: the pack is data, and `internal/routing` executes it.

## Two versions

`202409` and `202502` are the two versions the n8n package publishes. They are
**not** additive — operations move and parameters change between them — so each
is generated from its own document and registered as a distinct version of one
node type. A workflow imported at `202409` keeps resolving against the `202409`
definition.

## Why the node type is `pack.waha`

`node.BuiltinPrefix` reserves `kilasflow.` for nodes compiled into this binary,
so a pack registering into it could shadow one this project ships. The foreign
type string `@devlikeapro/n8n-nodes-waha.WAHA` stays where a reader wants it —
in the import diagnostics — rather than in the node type.
