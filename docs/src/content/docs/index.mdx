KilasFlow runs workflows: a graph of nodes, started by an HTTP request, a cron
schedule, an event from your app, another workflow or a person pressing a
button. Runs go through a durable queue that survives a restart. It is Apache-2.0,
written in Go, and ships as one binary with the editor inside it. SQLite is the
default store, so trying it takes no infrastructure.

This site is written for the engineer who is putting KilasFlow into a product.
Pick the track that matches what you are building.

## Not an integrator?

- **Evaluating KilasFlow.** [What KilasFlow is](/start/what-kilasflow-is/) says
  what works today and what does not, in that order.
- **Running it.** [Install](/start/install/) gets one binary running.
  [Deployment](/operate/deployment/) and [Deploy for SaaS](/operate/deploy-for-saas/)
  cover production, and [Security posture](/operate/security/) says what is and
  is not defended.
- **Writing workflows.** The [execution model](/concepts/execution-model/),
  [expressions](/concepts/expressions/) and [triggers and
  webhooks](/concepts/webhooks/) pages describe how a workflow behaves. The
  [node catalogue](/reference/node-catalogue/) lists every node.
- **Coming from n8n.** The workflow document is a reimplementation of n8n's
  interchange format, with an importer and an exporter and no n8n code. See
  [Migrating from n8n](/guides/n8n-migration/).
- **A coding agent.** The binary embeds a skills bundle and an MCP server, and
  this site publishes [`llms.txt`](/llms.txt) and [`llms-full.txt`](/llms-full.txt).

## What is not built yet

The site documents the system that exists on `main`. The gaps an integrator is
most likely to hit are listed, not hidden: there is no single sign-on, the
server does not push execution results to your backend, and the SDK is not on
npm yet. [Get notified of results](/guides/get-notified/) covers the second one
and [Using the host SDK](/guides/sdk/#install-from-a-checkout-until-the-first-release)
the third.
